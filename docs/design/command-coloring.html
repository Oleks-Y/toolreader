Command coloring: pick a style and themes

Every row below is taken from the session in your screenshot, plus a few common ones (cargo, go, pnpm, gh, git push). Hue = what the command does; token type inside a command (flag, string, path) only changes brightness or italics, so it can't be confused with a category.

v2: palettes are generated on a fixed hue wheel (one hue per category, alternating lightness) and every pair of categories is checked for perceptual distance (OKLab ΔE ≥ 0.075). v1 had clashes such as go = search in Tokyo Night. v3: toolchain colors are gone; commands are colored by intent (setup, build, run, test), whatever the toolchain.

MCP own color for the server (t3-code) and a lighter shade for the tool (preview_click); JSON args dimmed
Read-only read (cat/sed/head/tail) and search/list (rg/grep/find/ls) are close shades of one color
Writes write, sed -i, rm/mv/cp, file edits: one warm color
git / gh their own color. Read-only git (status, diff, log) uses the same hue but dimmer
docker its own color (docker, compose, kubectl)
setup installs and fetches, any toolchain: pnpm install, uv pip install, go mod download, cargo fetch, brew install
build compiles and checks: vp build, go build, cargo build, tsc, typecheck, lint
run dev servers, scripts and anything unrecognized: pnpm dev, go run, cargo run, python3 script.py, make …
test every test run: go test, vp test, cargo test, bun test, pnpm test, pytest, vitest, jest
Other web fetch/search is a shade of the read family; subagents are white (black on light)
