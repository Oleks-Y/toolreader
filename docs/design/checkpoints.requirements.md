# Checkpoints: requirements

What the checkpoint feature must do (functional) and how well (non-functional), as specified on 2026-10-11. Sources: `docs/spec.md` (Checkpoints), `docs/design/checkpoint-scope.md`. Each requirement says how it is checked and where it stands:

- **built**: in the branch, with tests.
- **planned**: agreed, not built.

## Decisions this list encodes

- The CLI is a versioned client. A versioned backend owns Postgres behind `/v1`, with workspaces.
- Only sessions linked to the commits in scope are stored, never every session on the machine.
- **Upload happens at push only.** Commit time sends nothing over the network.
- Hooks act only in repos that opted in.
- Without a backend configured, the CLI still writes straight to Postgres (`TOOLREADER_DATABASE_URL`). Whether to keep that mode is open.
- The relevance judge (Jev) is deferred. CI upload and coverage reports are out for now.
- No images.

### Backend

| ID    | Requirement                                                                                                                                                                                                                                                                                                                | Checked by                           | Status |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | ------ |
| FR-B1 | Endpoints, under `/v1`: `GET /health`, `GET /meta`, `POST /workspaces/:ws/checkpoints`, `GET /workspaces/:ws/checkpoints/:id`, `GET /workspaces/:ws/repos/:repo/commits/:sha/checkpoints`, `GET /workspaces/:ws/threads/:threadId/checkpoints`, `POST /workspaces/:ws/repos/:repo/rewrites`.                               | `Backend.test.ts`                    | built  |
| FR-B2 | Every request except `health` needs a bearer token. Each token belongs to one workspace: an unknown or revoked token gets `401`, another workspace gets `403`. Only a token's SHA-256 is stored; `backend token create` prints the token once.                                                                             | `Backend.test.ts`                    | built  |
| FR-B3 | Upload is a batch of 1–100 records with one result per record. Each record is decoded against the `Checkpoint` union, its key is recomputed (`key-mismatch`), and the redactor re-checks it (`not-redacted`). A newer format is `unsupported-format`, a malformed record is `invalid`. A bad record never fails the batch. | `Backend.test.ts`                    | built  |
| FR-B4 | Writing is idempotent: `inserted`, `exists` (same content), `differs` (stored copy kept), or `replaced` (only with `replace=true`). The content hash ignores when the record was taken, the client version, the session name, and where HEAD and the branch were.                                                          | `CheckpointStore.test.ts`; API tests | built  |
| FR-B5 | A commit's history is found by SHA, then through recorded rewrites (any depth, cycles stop, 50 at most), then by patch-id. Each record counts once, strongest match first, newest first on ties.                                                                                                                           | `CheckpointStore.test.ts`            | built  |
| FR-B6 | Only the backend runs migrations. It refuses a database migrated by a newer version, or whose migration history was edited.                                                                                                                                                                                                | `PgMigrations.test.ts`               | built  |
| FR-B7 | Workspaces isolate data: no endpoint returns or changes another workspace's records.                                                                                                                                                                                                                                       | `Backend.test.ts`                    | built  |

## Out of scope now

- **Upload at commit time.** Later, keep reserve copies of records whose session could be deleted before the push.
- **CI upload** of sessions that ran in CI.
- **Coverage reports per PR.**
- **The relevance judge (Jev).**
- **Images.**
- **Deleting checkpoints through the API.**

## Open

- Where the backend runs: hosted per team, or local per developer (same image).
- Auth beyond per-developer tokens, and access per repo inside a workspace.
- Does the CLI keep a direct-to-Postgres mode? Proposal: no.
- Admin delete for privacy requests.
