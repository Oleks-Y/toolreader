# Checkpoint scope: only what a commit or PR links

Checkpoints store sessions for commits, not sessions on the machine. The unit is a link, one (commit, session, role) at a time, and its history is the session's window for that commit. A session that links to no commit in scope is never stored. A session that only looks related is shown for a decision and is not stored until someone decides.

Code: `src/core/linking.ts` (`linkCommits`, `signalsFor`, `selectScope`), `Ledger.scope` (loads a range and runs both), `checkpoint collect` (`src/server/checkpoints/checkpointCli.ts`). `ledger sync` uses `linkCommits` too, so the ledger and checkpoints link the same sessions.

## The border

A session is in scope for commit C when all of the following hold.

1. **Repo.** Its directory is inside a worktree of C's repo (`git worktree list`), and that repo opted in (`checkpoint hook install` sets `git config toolreader.checkpoints true`). An explicit `--range`/`--pr`/`--sha` counts as opting in for that run.
2. **Link.** `linkCommits` links it to C. Strongest first: an `Agent-Session` trailer, C's SHA printed by its `git commit`, its `git commit` just before C, `--session`/`--match-sessions`, or edits to C's files from C's worktree (`evidence`). Nothing else is enough.
3. **Window.** Only the segment the link names is stored: from the commit's parent (or the session's previous commit action) up to C. The rest of the session is not stored.

Everything else is either a **candidate** (a session in C's worktree whose window shows a signal, see below), which goes to `candidates` and is never stored by itself, or it is **out**: not listed and not loaded past its summary.

## Signals for sessions the ledger can't link

Some agents (Pi, and Codex or Claude when they edit through the shell) have no edit or read tool, so `editedPaths` sees only what `humanizeCommand` parses: `>`, heredocs, `sed -i`, `cp`, `mv`, `rm`. Everything else becomes a typed signal. Signals never link by themselves: a person decides (`ledger link`), and a relevance judge may later (deferred); no more parsing rules (decided 2026-10-11). Each signal lists the entry ids that show it and the commit files it names:

| Kind (strongest first) | Shows                                                                                                                                                                                                |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `write`                | `git apply`, `patch`, `apply_patch` through the shell (diff headers in the heredoc, or `patching file` / `Applied patch` in the output); `git mv`, `git rm`, `git restore`, `git checkout -- <path>` |
| `staged`               | `git add <path>`, or `git add -A`/`.`/`-u` and `git commit -a` (these name no path)                                                                                                                  |
| `script`               | any non-read command whose words or inline code name a commit file (`python - <<EOF`, `node -e`, `prettier --write`)                                                                                 |
| `inspected`            | `git diff`, `status` or `show` naming a commit file in its arguments or output                                                                                                                       |
| `read`                 | a read tool or reader command on a commit file                                                                                                                                                       |
| `active`               | any action in the commit's worktree between its parent and it                                                                                                                                        |

Paths match exactly as `editedPaths` matches them (`commitPathMatcher`): an absolute path counts only inside a worktree of the repo, so `/tmp/x/src/a.ts` is not `src/a.ts`. Signals are computed only for sessions in the commit's own worktree (`here`), and not for merges.

## Decisions (2026-10-11)

1. **Signals don't link.** `write` and the other signals (and commands like `tee` or `perl -i`) stay inputs for a person (and, later, the deferred relevance judge); no new parsing rule turns them into ledger evidence.
2. **Link order.** Commits without a trailer use the full `linkCommits` order: trailer, printed SHA, time, `--session`/`--match-sessions`, evidence. (The earlier decision was only that a commit a person makes in a terminal, with no trailer, gets no checkpoint.)
3. **Relevance judge: deferred** (2026-10-11). Out of scope for now.
4. **`--pr` "here".** The worktree whose HEAD is the PR head, else the one running the command.
5. **`unlinked`.** `collect` skips those threads; a stored checkpoint is not deleted.
6. **Subagents.** A linked session's subagent threads are taken only when they link by themselves.
